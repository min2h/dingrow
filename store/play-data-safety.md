# Play 데이터 보안 답변 초안

계정은 아직 없습니다. Play Console의 데이터 보안 양식에 아래를 옮기면 됩니다. 앱이 수집하거나 공유하는 데이터는 없습니다.

## 데이터 수집

| 질문 | 답 |
| --- | --- |
| 앱이 사용자 데이터를 수집하거나 공유하나요? | 아니요 |
| 데이터가 전송 중 암호화되나요? | 해당 없음. 서버로 보내지 않습니다. |
| 사용자가 데이터 삭제를 요청할 수 있나요? | 앱을 지우면 기기 안의 데이터베이스가 삭제됩니다. 별도 계정 데이터는 없습니다. |
| 데이터가 독립적인 보안 검토를 받았나요? | 아니요 |
| 광고 또는 마케팅 목적의 데이터 | 없음 |
| 광고 ID | 쓰지 않음 |
| 계정, 이름, 이메일, 전화번호, 위치, 사진, 연락처, 금융 정보 | 수집하지 않음 |

펫 이름과 일정 제목은 사용자가 기기에 입력하고 SQLDelight 데이터베이스(`dingrow.db`)에만 남습니다. 같은 폴더에 예전 파일 `mongle.db`가 있고 `dingrow.db`가 없으면 한 번 복사합니다. Play의 “수집”은 개발자 서버로 나가는 데이터를 뜻하므로, 이 로컬 저장은 수집으로 신고하지 않습니다.

## 권한과 쓰는 이유

| 권한 | 이유 | Play 양식 |
| --- | --- | --- |
| `POST_NOTIFICATIONS` | 일정 시각에 확인 / 5분 뒤 / 완료 알림을 보여 줍니다. | 알림 권한. 거부 가능. |
| `SCHEDULE_EXACT_ALARM` | 리마인더를 정시에 울립니다. 사용자가 설정에서 알람 및 리마인더를 허용한 뒤에만 `setExactAndAllowWhileIdle`을 호출합니다. 허용하지 않으면 15분 안쪽의 부정확한 알람으로 바꿉니다. | 정확한 알람 선언이 필요합니다. 핵심 기능은 “사용자가 만든 일정의 리마인더”입니다. 캘린더가 아니라 앱 안의 할 일입니다. |
| `USE_EXACT_ALARM` | 쓰지 않습니다. 이 권한은 Play가 알람 시계·캘린더 등으로 제한합니다. | 선언하지 않음 |
| `RECEIVE_BOOT_COMPLETED` | 재부팅과 앱 업데이트 뒤 다음 알람을 다시 등록합니다. | 민감 권한이 아님 |
| `VIBRATE` | 알림 진동 | |
| `WAKE_LOCK` | 정확한 알람이 울리는 동안 기기를 잠깐 깨웁니다. | |

정확한 알람 선언문 초안:

> 딩그로(Dingrow)는 사용자가 직접 만든 할 일의 시각에 알림을 보냅니다. 정시에 울려야 일정을 놓치지 않으므로 SCHEDULE_EXACT_ALARM을 사용합니다. 사용자가 시스템 설정에서 끈 경우에는 부정확한 알람으로 동작합니다.

## iOS 개인정보 영양 라벨

- 데이터 수집 항목: 없음 (Data Not Collected)
- 추적: 아니요
- 계정 연동: 없음
- App Group `group.app.dingrow`는 앱과 위젯이 같은 기기의 데이터베이스를 보기 위한 것이고, 기기 밖으로 나가지 않습니다.
